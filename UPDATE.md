# Updating al-folio

This site is a customized fork of
[`alshedivat/al-folio`](https://github.com/alshedivat/al-folio). Keep updates
reviewable by merging upstream release tags into a short-lived update branch, then
testing locally before merging back to `main`.

## Preferred Workflow

1. Start from a clean worktree. Commit or stash local changes first.

   ```bash
   git status --short
   ```

2. Make sure the upstream remote exists. This only needs to be done once.

   ```bash
   git remote add upstream https://github.com/alshedivat/al-folio.git
   ```

   If the remote already exists, verify it instead:

   ```bash
   git remote -v
   ```

3. Fetch upstream branches and tags.

   ```bash
   git fetch upstream --tags
   ```

4. Create an update branch from current `main`.

   ```bash
   git checkout main
   git pull --ff-only origin main
   git checkout -b update/al-folio-vX.Y.Z
   ```

5. Merge the upstream release tag.

   ```bash
   git merge vX.Y.Z
   ```

   Use the concrete release tag, for example `v0.16.3`. Prefer release tags over
   `upstream/main` so updates are tied to a known al-folio release.

6. Resolve conflicts by preserving this site's content and deployment settings while
   accepting upstream theme internals where possible.

7. Build and test locally.

   ```bash
   docker compose up --build
   ```

   Visit `http://localhost:8080` and check the home page, publications, blog, news,
   projects, CV, search, and light/dark mode.

8. If Docker or lockfile errors appear after an upstream update, follow
   `LOCAL_DOCKER_NOTES.md`.

9. Commit the resolved update.

   ```bash
   git add .
   git commit -m "Update al-folio to vX.Y.Z"
   ```

10. Merge or open a pull request back to `main`, then let GitHub Pages deploy from the
    generated `gh-pages` branch.

## Conflict Priorities

Preserve these local values unless the deployment target intentionally changes:

```yaml
url: https://pablormier.github.io
baseurl:
```

Keep personal content in:

- `_pages/`
- `_posts/`
- `_news/`
- `_projects/`
- `_bibliography/papers.bib`
- `_data/`
- `assets/img/`
- `assets/json/resume.json`

Pay special attention to likely conflict files:

- `_config.yml`
- `Gemfile`
- `Gemfile.lock`
- `package-lock.json`
- `_data/socials.yml`
- `_includes/social.liquid`
- `_includes/metadata.liquid`
- `_scripts/search.liquid.js`
- `README.md`
- `CUSTOMIZE.md`
- `INSTALL.md`

## Maintenance Policy

- Do not edit `gh-pages`; it is generated by deployment.
- Keep personal customizations concentrated in content, data, assets, and the smallest
  necessary `_config.yml` changes.
- Avoid modifying theme internals unless there is a clear site-specific need.
- When removing upstream demo content, prefer `_config.yml` `exclude:` entries over
  deleting files, because that reduces future merge conflicts.
- Commit regenerated lock files with the upstream update that required them.
